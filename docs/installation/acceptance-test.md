# 安装与验收测试方案

本方案用于 Agent 和零基础用户确认“能下载、能安装、能启动、能识别、能恢复”，不能只以网页打开为成功。

## 一、安装前报告

Agent 自动检测并展示：

| 项目 | 通过条件 | 处理方式 |
|---|---|---|
| 系统 | macOS 14+ Apple Silicon；Windows 10 22H2/11 x64 | 不支持则暂停；Linux 当前无离线包 |
| 内存 | 16 GB 推荐；8 GB 最低 | 8 GB 标记降级并增加预计时间；低于 8 GB 暂停 |
| 磁盘 | 10 GB 最低；15 GB 推荐 | 不足则让用户选择清理或其他目录 |
| 工具 | macOS curl/tar/shasum；Windows PowerShell 5.1+/tar | 缺失时说明官方修复方式 |
| Windows 运行库 | Visual C++ 2015–2022 x64 | 缺失时只使用微软官方安装包 |
| 端口 | 优先 8000/8080/8082 | 被占用时记录占用者并使用备用端口，不杀未知进程 |
| 许可用途 | 用户明确用途 | 机构/生产用途先核对授权 |

报告还必须列出目标路径、macOS 4 个、Windows 6 个下载文件、macOS 约 1.65 GiB/166 wheels 或 Windows 约 1.61 GiB/164 wheels，以及预计下载和安装时间。

## 二、下载与安装测试

1. 优先国内镜像，失败后切换 GitHub；保留断点续传文件；
2. 下载 20–30 秒后根据实际速度更新 ETA；
3. 使用 `SHA256SUMS` 校验 runtime、HaS、PaddleOCR，任一失败不得安装；
4. 运行双击安装入口，确认四个阶段均完成：模型校验/解压、Python、离线依赖、导入检查；
5. 中途失败时记录阶段和错误，不删除模型包、成功下载或日志。

## 三、启动与服务测试

运行双击启动入口。启动器应：

1. 只停止上次由 PrivacyGuard 启动的进程；
2. 自动选择可用端口；
3. 写入 `.run/runtime.json` 或 `.run/runtime.env`；
4. 等待后端、HaS、OCR reachable，且 OCR ready；
5. 写入 `logs/last-check.json`；
6. 自动打开实际应用地址。

然后运行检测入口，验收值必须为：后端 `online`、HaS `online`、OCR `online`、`ocr_ready=true`、总结果 `passed`。standard 模式不要求 LocateAnything 在线。

## 四、功能测试

只使用虚构材料：

1. 上传包含虚构姓名、电话、身份证号、银行卡、地址和公司名的 TXT，确认至少识别出配置中启用的类型；
2. 上传一份虚构扫描 PDF，确认 OCR 有文字和坐标结果；
3. 执行涂黑或假名化导出，确认文件可以打开、页数一致；
4. 搜索导出 PDF，确认被处理的原敏感文字不可检索；
5. 切换侧栏、返回文件并刷新页面，确认文档和处理状态可恢复；
6. 停止后重新启动，确认应用仍可读取本地历史数据。

如任何一步失败，最终状态为“基础服务通过、功能验收失败”，不得笼统宣称安装成功。

## 五、端口冲突测试

测试人员可先让一个无关程序占用 8000，再启动 PrivacyGuard。预期结果：无关程序保持运行；PrivacyGuard 自动使用 18000；浏览器打开 `http://127.0.0.1:18000`；检测报告中的地址一致。8080/8082 用同样方法验证。

## 六、中断恢复测试

至少验证一次下载中断和一次安装失败：

- 下载恢复后，已校验成功的文件不重复下载；
- pip/导入失败时安装器必须非零退出，不能打印“安装完成”；
- 修复后重新执行可覆盖不完整虚拟环境，不要求重新下载模型；
- 日志和 SHA-256 结果仍可提供给 Agent。
