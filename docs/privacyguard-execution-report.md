# PrivacyGuard 执行与数据暴露检查报告

## 1. 报告目的

记录一次 PrivacyGuard 受保护文档分析的输入、输出、处理过程和数据暴露边界，为开发线程排查与修复问题提供依据。

## 2. 测试输入

用户要求：

- 使用 `$privacyguard` 扫描本地合同样本。
- 仅在扫描通过后读取安全内容。
- 基于安全内容总结合同风险。
- 禁止宿主 Agent 直接读取原文件。

源文件路径：

```text
/Users/Apple/Documents/Project/Ryan/Law/002-Anonymize/PrivacyGuard/samples/fictional_contract.txt
```

传给 `privacy_scan_file` 的业务参数只有文件绝对路径，没有由宿主 Agent 读取或传递的文件正文。

## 3. 执行过程

1. 宿主 Agent 未使用 `cat`、`sed`、`rg` 或其他文件读取命令打开源文件。
2. 调用 `privacy_scan_file(file_path)`，由 PrivacyGuard 扫描文件。
3. 扫描返回 `approved`、实体计数、文件类型、解析器、安全引用和过期时间。
4. 宿主 Agent 使用扫描返回的 `safe_reference` 调用 `privacy_get_safe_content`。
5. `privacy_get_safe_content` 返回状态为 `approved` 的脱敏文本。
6. 宿主 Agent 仅基于脱敏文本总结合同风险。
7. 本次未调用 `privacy_secure_ask`，因此未要求 PrivacyGuard 将内容提交给其配置的 LLM。

流程如下：

```text
用户提供路径
    |
    v
privacy_scan_file
    |
    +-- blocked/error --> 停止，不读取正文
    |
    +-- approved
          |
          v
    返回 safe_reference
          |
          v
privacy_get_safe_content
          |
          v
仅分析脱敏后的安全文本
```

## 4. 扫描输出

扫描状态：

```text
approved
```

检测到的实体数量：

```json
{
  "PROJECT": 3,
  "ORGANIZATION": 2,
  "PERSON": 1,
  "PHONE": 1,
  "EMAIL": 1,
  "ID_NUMBER": 1
}
```

文件处理信息：

```json
{
  "file_type": "txt",
  "parser": "local"
}
```

安全引用是临时访问凭证，本报告不记录其具体值。

## 5. 安全内容输出

`privacy_get_safe_content` 返回的敏感字段均已替换为类型化占位符。结构示例如下：

```text
<PROJECT_001>

甲方：<ORGANIZATION_001>
联系人：<PERSON_001>
电话：<PHONE_001>
邮箱：<EMAIL_001>
虚构测试身份证：<ID_NUMBER_001>

乙方：<ORGANIZATION_002>
双方约定仅将本合同用于 <PROJECT_002> 的 <PROJECT_003>，不构成真实交易。
```

安全内容保留了未被识别为敏感信息的合同语义，因此可以继续分析文本用途、条款完整性和可执行性风险。

## 6. 合同风险分析输出

基于安全内容得出的主要风险：

- 文本明确表示不构成真实交易，通常不足以证明双方具有建立真实合同关系的意思表示。
- 缺少交易标的、价款、履行方式、期限和验收标准等核心条款。
- 未约定违约责任、解除条件、适用法律和争议解决方式。
- 文本更接近系统测试声明，不适合作为真实交易合同使用。
- 测试文件包含证件号等高敏感字段，应评估收集必要性，并采用虚构数据及访问、留存限制。

## 7. 数据暴露检查

本次执行未发现原始敏感值进入宿主 Agent 上下文或最终用户回复。

| 数据类型 | 是否进入宿主 Agent 上下文 | 说明 |
| --- | --- | --- |
| 原始姓名 | 否 | 仅看到 `<PERSON_001>` |
| 原始电话 | 否 | 仅看到 `<PHONE_001>` |
| 原始邮箱 | 否 | 仅看到 `<EMAIL_001>` |
| 原始证件号 | 否 | 仅看到 `<ID_NUMBER_001>` |
| 原始组织名称 | 否 | 仅看到组织占位符 |
| 原始项目名称 | 否 | 仅看到项目占位符 |
| 文件绝对路径 | 是 | 用户主动提供，并传给扫描工具 |
| 实体类型及数量 | 是 | 扫描结果元数据 |
| 临时安全引用 | 是 | 用于取回安全内容 |
| 脱敏后的合同内容 | 是 | 用于完成风险分析 |
| 未被识别为敏感的合同语义 | 是 | 安全内容的一部分 |

## 8. 安全边界说明

- PrivacyGuard 扫描服务必须在本地读取源文件，才能识别并脱敏内容；“未读取原文件”是指宿主 Agent 没有直接读取源文件正文。
- 文件路径会进入工具调用参数。路径本身如包含敏感信息，需要单独考虑最小化或脱敏。
- `safe_reference` 具有临时访问能力，应按敏感令牌处理，不应长期记录在日志、报告或错误信息中。
- 脱敏文本以及未被识别为敏感的语义会进入宿主模型上下文。
- 自动检测只能降低暴露风险，不能证明不存在漏检。

## 9. 建议排查的问题

### 9.1 `PROJECT` 实体可能过度识别

本次共识别 3 个 `PROJECT` 实体，其中可能包括标题或普通业务用途描述。若这些内容并非敏感信息，过度脱敏会损失合同语义，降低后续分析质量。

建议检查：

- `PROJECT` 识别器的触发规则和置信度阈值。
- 标题、用途描述与真实项目名称之间的区分逻辑。
- 是否允许按策略关闭低风险实体类型的替换。

### 9.2 MCP 结果可能被重复展示

工具结果可能同时包含文本内容与 `structuredContent`。若调用端同时打印两者，同一 JSON 会在调试输出中出现两次。

建议检查：

- MCP 客户端是否应优先消费 `structuredContent`。
- 文本内容是否只应用作不支持结构化结果时的兼容回退。
- 日志层是否可以对相同结果去重。

### 9.3 安全引用的日志暴露

本次安全引用曾在工具调用链中用于获取安全内容。虽然它具有有效期，但仍属于临时凭证。

建议检查：

- 工具调用日志是否默认记录完整参数。
- 是否可在日志展示层对 `safe_reference` 做掩码处理。
- 引用是否具备短有效期、单次使用或调用方绑定机制。

## 10. 结论

本次受保护流程按预期完成：先扫描、通过后凭安全引用获取脱敏内容，再进行合同风险分析。未观察到姓名、电话、邮箱、证件号、组织名称或项目名称等原始值泄露给宿主 Agent 或出现在最终回复中。

当前应重点检查 `PROJECT` 过度识别、MCP 结果重复展示，以及 `safe_reference` 在调试日志中的可见性。
