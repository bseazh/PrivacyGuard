# 数据流、安全边界与明确缺口

核对日期：2026-11-04。主要依据 `core.py`、`semantic.py`、`store.py`、`config.py`、RedactionEverything 适配器和 `gateway/` 代码。

## 三个入口不能混为一谈

| 入口 | 输入与输出 | 当前边界 |
|---|---|---|
| MCP | 获准目录内文件路径 → 答案/统计；明确下载时附安全副本 | 文件解析/OCR、引用与安全导出；不自动经过网关 |
| Gateway | 鉴权后的非流式文本消息 → 经检查的回答与请求 ID | Channel 授权、动作版本、Trace；拒绝附件、图片、tools、Responses 和流式 |
| 桌面文档操作 | 人工选择材料、复核和导出 | 多种假名、映射导出、原位 PDF 等能力不能套用到 MCP/网关 |

宿主 Agent 在调用 MCP 前可能已读取文件；Skill 是协作约定，无法强制接管宿主全部行为。Gateway 只保护实际发送到它的请求，不能阻止用户绕过地址直接调用其他模型。

## 数据在哪里，谁能看到

| 数据 | 处理位置 / 接收者 | 保存与清理现状 |
|---|---|---|
| 用户原文件 | 用户指定路径；本机解析服务 | 不因引用到期而删除原件 |
| 上传副本、解析文本、NER 结果 | RedactionEverything 本机服务；HaS 接收原文窗口 | 后端上传/输出等目录受服务配置控制；未统一实现保留期和自动清理 |
| 临时文本窗口 | 适配器临时 TXT → 本机后端上传接口 | 本地临时目录上下文结束后清理，不等于后端上传副本同时删除 |
| Presidio 检测输入 | 配置的 Presidio 服务 | 接收原文及复检文本；部署者必须确认服务地址、日志和访问权限 |
| MCP 获准文本及引用 | 默认 `~/.privacyguard/approved/`，可由 `PRIVACYGUARD_DATA_DIR` 改变 | 引用 JSON 保存 token、安全文本或副本路径、摘要及统计；目录/文件权限限制访问，但并非加密数据库 |
| MCP 安全副本 | approved 目录 | 引用读取校验文件摘要和路径；到期不代表副本已删除 |
| Gateway 映射 | 当前请求内存 | 不写入 Trace，无持久化授权回填库；不承诺操作系统内存取证抵抗 |
| 发往分析模型的消息 | LiteLLM → 当前配置上游 | 网关当前限定本机回环上游；MCP 模型配置需另行核对，不能据此断言任何部署都不出机 |
| Gateway Trace / 管理记录 | 状态目录 `state.sqlite3` | 保存 ID、版本、动作、计数、耗时等，不保存正文；尚无自动保留期、清理或生产备份恢复 |
| 管理员密码 / 客户端配置 | 状态目录 `admin-login.txt` / `client.json` | 明文凭据文件用于本机接入；数据库另存密码校验值/Key 摘要。禁止提交或附到排障报告 |

安全引用默认 TTL 为 900 秒。`SafeReferenceStore.get` 在读取过期引用时拒绝并移除其 JSON；没有全目录定时到期清理，且不自动删除副本。**凭证失效与数据物理删除是两件事。** 不承诺磁盘安全擦除、备份自动同步删除或机器管理员无法读取本机文件。

## 保证与不保证

- 检测依赖失败、输入不支持、必要审计失败时停止，不静默切换为原文透传。
- 发送给分析模型之前和回答交付之前执行检查；原文仍需要交给本机识别服务，不能称为“所有模型都不见原文”。
- Trace 可以证明执行步骤和策略版本，不能证明模型零漏检或法律分析正确。
- OCR 页数覆盖能发现缺页/空页，不证明每个字、印章和表格关系均正确识别。
- 本机绑定、会话、CSRF 和 Key 检查不是生产多租户安全认证；本机管理员、恶意软件及被篡改依赖不在这些应用检查能够完全抵御的范围内。

## 明确缺口与处理顺序

| 优先级 | 缺口 / 已发现的说明差异 | 应如何验收 |
|---|---|---|
| P0 | 共享核心会合并重叠实体并丢失其他类型标签，网关后续 BLOCK 优先无法恢复全部原始候选 | 保留原始类型/来源；测试重叠 REDACT 不得掩盖 BLOCK |
| P0 | 真实材料标注尚不完整，不能给出可信总体召回率 | 按类型人工标注，报告漏检、误报、长文档尾部与 OCR 情景；原文不上传 GitHub |
| P0 | 上传副本、引用 JSON、安全副本、Trace 没有统一生命周期 | 明确保留期；测试到期、异常退出、备份和授权清理；不能误删原件 |
| P1 | 低置信度强制阻断并非覆盖所有语义类型；网关当前 PERSON 不在该阈值集合中 | 先定义姓名阈值/复核规则并验证误报，不把所有姓名自动阻断写成现状 |
| P1 | 策略固定了动作与引擎标识，未固定完整检测模型/服务部署依赖 | 请求关联模型、配置及版本；升级重新验收 |
| P1 | 管理员恢复、生产角色分权、Key 轮换流程、备份恢复仍不完整 | 独立验收恢复和最小权限；现有后台可重新发 Key，不必重建数据库 |
| P2 | 原生客户端协议、更多模型、授权回填未完成 | 分别建任务，不因 MCP 配置成功宣称网关兼容 |
