# PrivacyGuard 项目基线

## 已确认环境

- 首要平台：macOS Apple Silicon
- 当前开发机：macOS 14.8.1 (23J30)、Apple M2、16 GB 内存
- 产品阶段：内部试用
- 目标体验：律师下载安装后直接使用，不安装 Python、CUDA 或命令行依赖
- 默认推理：CPU 可运行；Apple Silicon 加速作为优化，不作为前置条件

## 测试材料位置

测试材料保留在外部资产目录，不复制进项目仓库：

- 本地脱敏测试资料目录（不提交到 Git）
- 本地真实材料目录（不提交文件名、路径或内容）

材料类型包括 PDF、DOCX、图片、TXT、CSV、XLSX、EML、VCF、ICS、JSON、ZIP 和 WAV。部分材料可能包含真实个人、案件或商业信息，因此开发阶段只使用必要文件，并避免把原文、提取文本或识别结果提交到 Git。

## 首轮测试分层

### P0：首版必须支持

- TXT / Markdown / EML 等纯文本
- DOCX
- 有文本层的 PDF
- 姓名、组织、手机号、身份证号、银行卡号、地址、案号、合同编号
- 识别结果人工确认
- Token 化和脱敏文本导出

### P1：首轮验证后加入

- 图片
- 扫描 PDF
- OCR 后的实体识别
- 图片版合同、聊天截图、回单和证据材料

### P2：记录需求，暂不进入第一版

- XLSX / CSV 结构化表格
- VCF 通讯录
- ICS 日历
- WAV 音频转写
- ZIP 递归处理
- 印章、签名、人脸等视觉对象定位

## 首版技术约束

1. 不直接复制或打包 RedactionEverything 上游代码。
2. 不使用 LocateAnything-3B 作为内部试用版默认组件，除非单独确认许可。
3. PDF 组件需在打包前确认商业/内部部署许可；不能默认依赖 PyMuPDF 的 AGPL 许可。
4. 模型和运行时由安装包或应用内自动安装提供，不能要求律师手动下载模型。
5. 原始文件、映射表和日志默认保存在本机；测试输出与原始材料分开。

## 下一步验收

用一小批代表性材料比较三条路径：

1. 纯规则；
2. 纯本地 NER；
3. 规则 + 本地 NER。

记录召回率、误报率、人工修正次数、处理耗时、内存占用和导出结果可用性。先完成 P0，再决定是否扩大 OCR 和文件格式范围。
